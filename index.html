契约与后期迁移说明（点开）

首版范围：JavaScript / TypeScript / HTML / CSS 四门，全部在浏览器里跑。JS/TS 默认走 Worker（worker.terminate() 能真杀无限循环），HTML/CSS 走 sandbox="allow-scripts" 的 iframe。TypeScript 用官方 transpileModule 动态加载转译，只做语法转换。

契约先行：RunRequest 已含 target: browser | server、limits（wall/cpu/memory/output）、files[]、stdin；RunResult 已含 exitCode: number | null（浏览器没有退出码，不假装 0）、usage、probes、preview。能力表 Capability 由注册表 active() 推导 —— 没接线就置灰，单测骗不过去。

迁移到服务端：src/runners/server/piston.ts 已实现 Runner 接口、buildPistonBody()（显式传内存限额，不吃 Piston 默认的 -1）与 mapPistonResponse()（RE/SG/TO/OL/EL/XX 六种状态映射），默认 enabled: false 且不注册。启用只需在 createRegistry() 传 ServerWiring，UI 一行不用改；能力表会自动出现 server 位置与「可判分」。

已知边界：iframe 内同步死循环会冻结标签页（浏览器限制，不是实现缺陷），因此该模式的超时判据不做自动验证；JS/TS 请用 Worker 载体。首版不支持模块 import/export。预览 iframe 是 opaque origin，event.origin === 'null' 证明不了任何事，代码里靠 event.source + requestId 双重校验。

验收：npm run verify（类型检查 + 单测 + 构建，32 条单测全绿）；npm run smoke 用本机 Chromium + CDP 打开 ?selftest=1 跑真浏览器端到端判据（26 条：24 绿 / 2 条按白名单记账跳过）；npm run negative 改坏 CSS 接线精确红 1 条，npm run smoke:negative 掐断 iframe 消息回传精确红 10 条 —— 两层负例都证明判据不是「怎么改都全绿」。

体积基线：首屏入口 gzip 10.08 KB；CodeMirror 与各语言包、TypeScript 编译器（3.59 MB / gzip 1.03 MB）全部是独立动态 import chunk，不进首屏。后续每加一门 WASM 语言，先量首屏与 gzip 增量再合并。
