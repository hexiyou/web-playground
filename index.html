当前范围（v0.9）：JavaScript / TypeScript / HTML / CSS 四门浏览器原生，加上三门 WASM 语言 Lua 5.4、SQLite（SQL）、CPython 3.14（Pyodide），再加五门仅服务端语言 Go、PHP、Perl（Cygwin Perl 5.32）、R（Cygwin R 4.2.1） 与 Ruby（RubyInstaller 4.0.9 / x64-mingw-ucrt），共十二门。JS/TS 默认走 Worker（worker.terminate() 能真杀无限循环），HTML/CSS 走 sandbox="allow-scripts" 的 iframe，TypeScript 用官方 transpileModule 动态加载转译。三门 WASM 各自一个 module Worker，全懒加载，不运行就一个字节都不下载。Go / PHP / Perl / R / Ruby 没有浏览器载体，能力表里只有 server 一个位置，载体下拉会如实显示「仅服务端」。

Go 怎么跑：先 npm run server 启动本机执行节点（servers/local/，Go 单二进制、非 Docker、只绑 127.0.0.1），再选 Go 点运行。节点按 Piston v2 兼容子集提供 /api/v2/runtimes 与 /api/v2/execute：go build + 运行两阶段、仅标准库（GOPROXY=off 零外联）、附加 .go 文件同目录编译、每请求独立临时目录。可用 ?server=<url>&token=<token> 覆盖节点地址。能力表如实登记 isolation=process-only / trust=advisory（结果不可用于判分）、没有 CPU/内存/进程数内核限额、usage.memoryBytes 不填。

服务端与运行时配置（v0.6 起）：节点 servers/local/main.go 已抽成内建 builtinSpecs() 规格表，execute() 里不再有任何「语言 if 分支」。Go 是 build+run 两阶段、PHP / Perl / R / Ruby 是单阶段解释执行（响应不带 compile 字段），正好第一次真机跑通「编译缺省」分支。GET /api/v2/runtimes 每次真探测本机有没有解释器能报版本，探测不到就不登记 ⇒ 前端能力表自动置灰并给安装指引，不拿缓存的旧版本骗人。便携式运行时（不在 PATH、没写注册表）在后端配置即可：复制 servers/local/runtimes.json 成 runtimes.local.json（不入库），给对应语言填 path 绝对路径；disabled:true 可显式关掉某门语言（优先于 PATH 探测），path:"" 回退 PATH。网页前台不暴露这个选项，配置是否生效由 npm run check:node 的 62 条接口判据证明（source=config / 坏路径自动置灰 / disabled / PATH 回退 / 宿主风味 / 脚本包装器缺失置灰 / 环境净化），probes.runtimePathSource 也会如实回报。PHP 用 -d allow_url_fopen=0 -d allow_url_include=0 关 URL 包装器、php.ini 用宿主机默认；curl / sockets 扩展仍能联网，A′ 没有内核级网络隔离。启动仍是 npm run server。Ruby 是 PATH 直发现的第一门原生运行时：ruby.path 留空即可，节点回报 source=path；Perl / R 不在 PATH，必须配绝对路径。

Perl / Cygwin 运行时（v0.7，刻意选型）：这一门不用 ActivePerl / Strawberry Perl，而是指定 D:/cygwin64/bin/perl.exe（5.32.1、$^O=cygwin、不在 PATH、没写注册表），目的就是验证「本项目调用 Cygwin / MSYS2 / WSL 这类非原生 POSIX 运行时是否符合预期」。结果：跑通，无阻断性问题。它同时是手动配 path 的第一个真实用例：check:node 反证了把 path 清空后 PATH 里没有 perl ⇒ 能力表立刻置灰，不是碰巧被 LookPath 找到。节点探测一次输出 $^V|$^O，把宿主风味如实写进 runtimes[].flavor / probes.runtimeFlavor（不硬编码 cygwin，换挂 Strawberry / Linux perl 同一条 spec 不用改），判据再让解释器自报一次核对。默认示例用 use utf8 + binmode(STDOUT, ':encoding(UTF-8)') 配套输出中文。踩到并已落盘的坑（完整 10 条、15 项实测表见 servers/local/README.md §8 与手册 13.9）：① Git Bash 把中文 argv 按 cp936 传给 Cygwin 程序会静默空输出 ⇒ 测这类运行时一律走文件 + HTTP body；② 只写 binmode ':utf8' 不写 use utf8 会乱码；③ getcwd() 是 /cygdrive/c/...、分隔符是 /；④ 宿主 PATH 无 cygwin 仍能起 /bin/sh（Cygwin 自补 /usr/bin，dll 靠 exe 同目录）；⑤ Perl 5.26+ 把 . 移出 @INC，节点加 -I . 才能 require 'helper.pl'；⑥ IO::Socket::INET 可建 socket ⇒ probes.network=no-enforcement，别对外说「零外联」。CDP 抓包只覆盖浏览器 target，看不到节点进程的网络行为。

R / Cygwin 脚本型入口（v0.8，刻意选型）：何工这一门事先点明「R 解释器入口本质是 Bash 脚本而不是可执行文件，会不会冒出意料之外的问题仍是未知数」。D:/cygwin64/bin/r 确实是 8953 B 的 #!/bin/sh wrapper，不是 PE（同目录 Rscript.exe 才是原生可执行文件，但那不是本次要测的入口）。结果：确实出了三个意外，跑通了但靠的是通用包装 + 环境净化：① Windows CreateProcess 直接 exec 脚本报 WinError 193 ⇒ 节点新增通用 wrapEntry，用同目录 sh.exe <script> 包装；探测与执行必须共用同一套启动计划，否则「runtimes 能报出版本、点运行却 127」；② 继承宿主 Git Bash / MSYS2 环境时 sh.exe rc=127 且 stdout/stderr 全空 ⇒ 新增 envFromTool 重建干净 PATH / HOME / CYGWIN；③ 最贵的一条：宿主把安全删除守卫以 BASH_FUNC_RM%% / RMDIR%% / UNLINK%% 导出成 bash 函数，Cygwin sh 启动会 import 并覆盖 rm，R 启动脚本一调 rm 就命中 MSYS2 版 CRLF 脚本，stderr 混入 safe-bin/rm: $'\r': command not found；只剥 BASH_ENV 仍复现，最终 stageEnv() 无条件剥 BASH_FUNC_ 前缀并把变量名按大写归一化（Windows 的 Path/PATH/path 大小写不敏感）。不掩盖缺陷：本机 stats.dll 缺 cyglapack-0.dll，设 R_DEFAULT_PACKAGES=base 能盖掉告警但 requireNamespace("stats") 仍是 FALSE ⇒ 保留告警、probes.startupWarning 如实登记，判据押「自报 + 不可用时必须告警」。flavor 从 --version 的 Platform: 行动态解析，判据让 R 自报 R.version$os 核对，不硬编码 cygwin；serverSocket(0) 可监听 ⇒ probes.network=no-enforcement;serverSocket-available。完整 20 项实测表与 10 条坑清单见 servers/local/README.md §9 与手册 13.10；18 条 r/* 真机判据 + 62 条节点判据把上述每条都钉成可执行证据。

Ruby / PATH 直发现的原生 PE（v0.9）：与 R 正好是入口形态的两极。本机 C:\Ruby40-x64\bin\ruby.exe 是 33 KB 的 MZ/PE 可执行文件，ruby --version 报 ruby 4.0.9 … +PRISM [x64-mingw-ucrt]；PATH 里直接能找到，所以 runtimes.json 把 ruby.path 留空，节点照实回报 source=path，风味由 --version 里的 [platform] 动态解析成 mingw（换 Linux / macOS / Cygwin 同一条 spec 不用改）。不需要 wrapEntry / envFromTool，但 PATH 必须保留（Ruby 靠它找 DLL 与子进程）；节点只剥宿主 RUBYOPT / RUBYLIB / GEM_* / BUNDLE_*，避免把本机装的 gem 与启动期自动加载悄悄带进执行环境（check:node 故意注入 RUBYOPT=-rjson 反证净化生效）。三处实测差异：① Ruby 1.9+ 把 . 移出 $LOAD_PATH，节点用 -I . 让「附加 .rb 文件同目录可 require」与 Go/PHP/Perl 语义一致（require_relative 本来就可用）；② Windows 原生 puts / STDOUT.write 把 \n 写成 CRLF，与 Cygwin Perl / R 的 LF 相反 —— 节点不归一化（归一化会毁掉用户显式写出的 \r\n），probes.lineEndings=no-normalization;platform-native 如实登记，判据按解释器自报的风味押「该有的换行」，换 Linux 不误红；③ 中文与 stdin 原样 UTF-8（源码写文件、不走 shell argv），json / openssl 标准库可用，TCPServer 可监听 ⇒ probes.network=no-enforcement;TCPServer-available。第三方 gem 不做承诺：随机器安装情况变化，A′ 仍是 process-only / advisory、结果不可判分。完整实测表见 servers/local/README.md §10 与手册 13.11；18 条 ruby/* 真机判据与新增节点判据把上述每条都钉成可执行证据。

Lua 实现：wasmoon 1.16.0 跑在独立 module Worker 里，glue.wasm 用 Vite ?url 自托管（默认会去 unpkg，内网/离线不可用，已显式覆盖为同源地址）。Worker 先初始化引擎发 ready，主线程收到后才起墙钟计时 —— wasm 下载与实例化不算进用户代码预算；同步死循环靠 worker.terminate() 真杀。Lua 侧薄壳把 print/io.write 接到输出通道（绕开 Emscripten 行缓冲，无换行也不丢）、io.read 读契约注入的 stdin、os.exit 改成可读错误；第二个 .lua 文件挂到内存 FS，可用 dofile('/helper.lua') 加载。traceAllocations: true 让内存用量与上限都可计数，probes 里能读到 Lua 版本、wasm URL、实际内存用量。

SQL 实现：sql.js 1.16.0 / SQLite 3.54.1 同样跑在独立 module Worker，sql-wasm-browser.wasm 用 ?url 自托管并显式传 locateFile（glue 默认按 scriptDirectory 拼路径，在 module Worker 里不可靠）。不用 db.exec() —— 它会一次性把整个结果集物化进 JS 数组，输出限额根本挡不住内存；改用 iterateStatements + stmt.step() 逐行读，每 64 行批量回传，触到输出字节或行数上限立即停。同一次运行内多语句共享同一个 DB，第二个 .sql 文件作为初始化脚本先执行；NULL/BLOB 显式可读，中文不做全角宽度对齐。能力缺口如实登记：sql.js 没有 wasmoon 那样的 setMemoryMax，所以只有墙钟 + 输出字节 + 行数 + Worker 隔离四道闸，probes.memoryCapability 明写 no-allocator-cap，usage.memoryBytes 一律不填（不拿 0 冒充用量）。无限递归 CTE 靠 terminate() 真杀。

Python 实现：pyodide 314.0.7 / CPython 3.14.2 跑在独立 module Worker。与 Lua/SQL 的单文件 wasm 不同，core 分发是一整套固定文件名的目录（pyodide.asm.mjs / pyodide.asm.wasm / python_stdlib.zip / pyodide-lock.json），glue 按 indexURL 拼路径；Vite 会把 pyodide.mjs 打进带 hash 的 worker chunk，默认前缀必然指错，官方默认更是直接走 CDN。所以由 scripts/sync-pyodide.mjs 在 postinstall / dev / build 三处幂等生成 public/pyodide/（版本精确 pin，运行时产物不入库），Worker 显式传同源 indexURL。首版只跑标准库：core 分发不带 wheel、没有 micropip，禁止自动装包；import numpy 翻译成「第三方包 numpy 不在自托管清单里，不会向 CDN 装包」的可读错误，快速失败且绝不外联。输出用 setStdout/setStderr({batched})、stdin 用 setStdin({read}) 接契约注入的 UTF-8 字节；附加 .py 文件写进内存 FS 的 /pg/ 后可 import helper，路径按净结果判逃逸；顶层表达式返回值回显成 -- 返回值：5，PyProxy 用完 destroy()。引擎复用：正常执行完保留 Worker，靠每次新建的 globals 隔离变量（9.6 MB wasm 只 boot 一次，probes.engineReused 可计数），只有超时 / 取消 / 内部错误才 terminate() 并清空缓存。如实登记的边界：复用期间 sys.modules 共享，不是进程级隔离；没有 allocator 上限，usage.memoryBytes 不填；probes.packageCapability 明写 stdlib-only。

零外联是抓包证据，不是运行时自述：真机冒烟在 CDP 上开 Target.setAutoAttach（flatten），对挂上来的 worker target 逐个再 Network.enable，按已知包仓库域名判红；同时必须抓到 ≥3 条同源 /pyodide/ 资产请求，否则「外部 0 条」只是压根没监听到 Worker 的空证据，直接判失败。dev 与 dist 两层实测都是：同源 /pyodide/ 资产 4 条、外部请求 0 条。v0.6 补一条边界：CDP 只监听浏览器自己的 target，节点进程发出的网络请求它一条也看不到 —— 抓包证明的是前端资产同源自托管，不是节点侧禁网。服务端语言的网络口径只能靠 probes.network 如实登记 + check:node 的行为判据，二者都替代不了内核隔离。

契约先行：RunRequest 已含 target: browser | server、limits（wall/cpu/memory/output）、files[]、stdin；RunResult 已含 exitCode: number | null（浏览器没有退出码，不假装 0）、usage、probes、preview。能力表 Capability 由注册表 active() 推导 —— 没接线就置灰，单测骗不过去。加一门语言只要登记 + 实现 Runner + 注册 + 加示例 + 补端到端判据，UI 一行不改。

★ 服务端路线与官方推荐的分叉（务必别忘）：官方 Piston 推荐 docker run --privileged + 纯 cgroup v2 + Linux（原理是 Isolate inside Docker），官方不支持脱离 Docker，Windows 原生跑不了。本项目刻意选了 A′ 非 Docker 的本机进程节点，依据是威胁模型不同：团队内几个人跑自己的可信片段，不需要内核级隔离。代价是只有进程级限额、结果不可判分、不能对公网开放。一旦要跑不可信代码 / 对外开放 / 判分，必须回切官方 Docker + isolate，不能靠 token 把 A′ 当沙箱。完整决策依据、官方真值、回切清单见分析手册 第十三章 与 servers/local/README.md。

为回切预留的接缝（v0.5 已抽完）：① createRegistry(getMount, serverRunners: Runner[]) 由调用方注入 Runner 实例，不再有绑死 PistonConfig 的 ServerWiring；② trusted 改由 Runner 声明的 isolation / trust 推导（A′ 也是 server，但只有 advisory，不能按位置猜）；③ 服务端语言名从 LANG_DEFS 抽成各后端自有的 languageMap。线协议纯函数统一在 src/runners/server/protocol.ts，A′ 与官方 Piston 共用同一份限额传递与六码状态映射。将来切官方部署只换 main.ts 注入的那一行，契约 / UI / 路由 / 能力表 / 判据零改动。

已知边界：iframe 内同步死循环会冻结标签页（浏览器限制），该模式的超时判据不做自动验证；JS/TS 请用 Worker 载体。首版不支持模块 import/export。预览 iframe 是 opaque origin，event.origin === 'null' 证明不了任何事，代码里靠 event.source + requestId 双重校验。Lua 没有真实网络与文件 IO，每次运行新建引擎（变量不跨运行），没有 REPL session；SQL 是纯内存 DB，每次运行新建，不持久化到 IndexedDB，也没有真实文件/网络。Python 无 socket / threading / 子进程，标准库里凡是依赖这些的模块都不可用；引擎复用不是进程隔离，跨运行可能残留 sys.modules 状态；第三方包要等预置自托管 wasm wheel 才能开。构建时若干 Module "xxx" externalized 警告来自 wasmoon UMD 与 pyodide.mjs 里浏览器下不用的 node 内建模块，dev 与 dist 两层真机都已验证。A′ 节点的边界：无内核隔离（用户代码可读写本机文件、起子进程、联网）、默认 token 只是开发口令、没有 CPU/内存/进程数硬限额、Windows 上 kill 主进程不保证子进程一起退出；每次执行都要 go build（本机约 1.5 秒），且满 CPU 的 for{} 在本机会让编译与终止各慢约 5 秒，所以超时判据只押 status=TO，不押毫秒数。PHP 的边界：本机是 8.0.17（偏旧，片段验证够用，贴近生产建议换 8.3）、php.ini 与扩展随宿主机漂移、语法错误按 Piston 语义只进 stderr + 非零退出码而 run.status 仍为空（判据押 stderr 与 exitCode，不押 status=error）、URL 包装器关了但 curl/sockets 仍可联网。宿主机前置不会消失：每加一门服务端语言都要装工具链（或配 runtimes.local.json 的 path）+ 在节点 spec 表登记，跨机器版本不一致就没有可复现性。Cygwin Perl 的边界：它是 POSIX 视图（/cygdrive/c/、/ 分隔符、$^O=cygwin），与 Git Bash 的 MSYS2 是两套运行时，/tmp 不通用；perl.exe 只是 12.8 KB stub，cygwin1.dll / cygperl5_32.dll 必须与它同目录，只拷 exe 必然起不来；fork() / system() 出来的子进程在 Windows 上不保证随主进程一起被杀；IO::Socket::INET 可建 socket，A′ 没有内核级禁网，probes.network=no-enforcement 是如实登记而不是「零外联」；中文必须 use utf8 与 :encoding(UTF-8) 配套，只设 :utf8 会乱码（已有 perl/utf8-layer-trap 判据钉死）。Cygwin R 的边界：入口是脚本不是 exe，必须与同目录 sh.exe 一起可用，只拷 r 文件必然置灰（check:node E 场景反证）；同样是 /cygdrive/c/ POSIX 视图，与 Git Bash 的 MSYS2 两套；本机 R 安装不完整，缺 cyglapack-0.dll ⇒ stats 命名空间加载失败，sd() / lm() 不可用，启动告警保留不掩盖（换机器修好后 r/default-packages-truth 不会误红）；serverSocket(0) / system() 可用，A′ 没有内核级禁网；R 启动本身约 700 ms，超时判据只押 status=TO 不押毫秒；Cygwin fork() 出来的子进程在 Windows 上不保证随主进程一起被杀。脚本型入口的 PATH / HOME / BASH_FUNC_* 全部由节点重建与净化，宿主里另配的 R 环境变量不会带进执行环境。
