当前范围：JavaScript / TypeScript / HTML / CSS 四门浏览器原生，加上三门 WASM 语言 Lua 5.4、SQLite（SQL） 与 CPython 3.14（Pyodide）。JS/TS 默认走 Worker（worker.terminate() 能真杀无限循环），HTML/CSS 走 sandbox="allow-scripts" 的 iframe，TypeScript 用官方 transpileModule 动态加载转译。三门 WASM 各自一个 module Worker，全懒加载，不运行就一个字节都不下载。

Lua 实现：wasmoon 1.16.0 跑在独立 module Worker 里，glue.wasm 用 Vite ?url 自托管（默认会去 unpkg，内网/离线不可用，已显式覆盖为同源地址）。Worker 先初始化引擎发 ready，主线程收到后才起墙钟计时 —— wasm 下载与实例化不算进用户代码预算；同步死循环靠 worker.terminate() 真杀。Lua 侧薄壳把 print/io.write 接到输出通道（绕开 Emscripten 行缓冲，无换行也不丢）、io.read 读契约注入的 stdin、os.exit 改成可读错误；第二个 .lua 文件挂到内存 FS，可用 dofile('/helper.lua') 加载。traceAllocations: true 让内存用量与上限都可计数，probes 里能读到 Lua 版本、wasm URL、实际内存用量。

SQL 实现：sql.js 1.16.0 / SQLite 3.54.1 同样跑在独立 module Worker，sql-wasm-browser.wasm 用 ?url 自托管并显式传 locateFile（glue 默认按 scriptDirectory 拼路径，在 module Worker 里不可靠）。不用 db.exec() —— 它会一次性把整个结果集物化进 JS 数组，输出限额根本挡不住内存；改用 iterateStatements + stmt.step() 逐行读，每 64 行批量回传，触到输出字节或行数上限立即停。同一次运行内多语句共享同一个 DB，第二个 .sql 文件作为初始化脚本先执行；NULL/BLOB 显式可读，中文不做全角宽度对齐。能力缺口如实登记：sql.js 没有 wasmoon 那样的 setMemoryMax，所以只有墙钟 + 输出字节 + 行数 + Worker 隔离四道闸，probes.memoryCapability 明写 no-allocator-cap，usage.memoryBytes 一律不填（不拿 0 冒充用量）。无限递归 CTE 靠 terminate() 真杀。

Python 实现：pyodide 314.0.7 / CPython 3.14.2 跑在独立 module Worker。与 Lua/SQL 的单文件 wasm 不同，core 分发是一整套固定文件名的目录（pyodide.asm.mjs / pyodide.asm.wasm / python_stdlib.zip / pyodide-lock.json），glue 按 indexURL 拼路径；Vite 会把 pyodide.mjs 打进带 hash 的 worker chunk，默认前缀必然指错，官方默认更是直接走 CDN。所以由 scripts/sync-pyodide.mjs 在 postinstall / dev / build 三处幂等生成 public/pyodide/（版本精确 pin，运行时产物不入库），Worker 显式传同源 indexURL。首版只跑标准库：core 分发不带 wheel、没有 micropip，禁止自动装包；import numpy 翻译成「第三方包 numpy 不在自托管清单里，不会向 CDN 装包」的可读错误，快速失败且绝不外联。输出用 setStdout/setStderr({batched})、stdin 用 setStdin({read}) 接契约注入的 UTF-8 字节；附加 .py 文件写进内存 FS 的 /pg/ 后可 import helper，路径按净结果判逃逸；顶层表达式返回值回显成 -- 返回值：5，PyProxy 用完 destroy()。引擎复用：正常执行完保留 Worker，靠每次新建的 globals 隔离变量（9.6 MB wasm 只 boot 一次，probes.engineReused 可计数），只有超时 / 取消 / 内部错误才 terminate() 并清空缓存。如实登记的边界：复用期间 sys.modules 共享，不是进程级隔离；没有 allocator 上限，usage.memoryBytes 不填；probes.packageCapability 明写 stdlib-only。

零外联是抓包证据，不是运行时自述：真机冒烟在 CDP 上开 Target.setAutoAttach（flatten），对挂上来的 worker target 逐个再 Network.enable，按已知包仓库域名判红；同时必须抓到 ≥3 条同源 /pyodide/ 资产请求，否则「外部 0 条」只是压根没监听到 Worker 的空证据，直接判失败。dev 与 dist 两层实测都是：同源 /pyodide/ 资产 4 条、外部请求 0 条。

契约先行：RunRequest 已含 target: browser | server、limits（wall/cpu/memory/output）、files[]、stdin；RunResult 已含 exitCode: number | null（浏览器没有退出码，不假装 0）、usage、probes、preview。能力表 Capability 由注册表 active() 推导 —— 没接线就置灰，单测骗不过去。加一门语言只要登记 + 实现 Runner + 注册 + 加示例 + 补端到端判据，UI 一行不改。

迁移到服务端：src/runners/server/piston.ts 已实现 Runner 接口、buildPistonBody()（显式传内存限额，不吃 Piston 默认的 -1）与 mapPistonResponse()（RE/SG/TO/OL/EL/XX 六种状态映射），默认 enabled: false 且不注册。启用只需在 createRegistry() 传 ServerWiring，能力表会自动出现 server 位置与「可判分」。

已知边界：iframe 内同步死循环会冻结标签页（浏览器限制），该模式的超时判据不做自动验证；JS/TS 请用 Worker 载体。首版不支持模块 import/export。预览 iframe 是 opaque origin，event.origin === 'null' 证明不了任何事，代码里靠 event.source + requestId 双重校验。Lua 没有真实网络与文件 IO，每次运行新建引擎（变量不跨运行），没有 REPL session；SQL 是纯内存 DB，每次运行新建，不持久化到 IndexedDB，也没有真实文件/网络。Python 无 socket / threading / 子进程，标准库里凡是依赖这些的模块都不可用；引擎复用不是进程隔离，跨运行可能残留 sys.modules 状态；第三方包要等预置自托管 wasm wheel 才能开。构建时若干 Module "xxx" externalized 警告来自 wasmoon UMD 与 pyodide.mjs 里浏览器下不用的 node 内建模块，dev 与 dist 两层真机都已验证。

验收：npm run verify（类型检查 + 58 条单测 + 构建）；npm run smoke 用本机 Chromium + CDP 打开 ?selftest=1 跑真浏览器端到端判据（74 条：72 绿 / 2 条按白名单记账跳过，跳过的正是 iframe 同步死循环两条）；npm run smoke:preview 在 dist 产物里跑同一套判据，验证 build 后 wasm 资源路径仍能加载。九个拆线负例：单测层 negative（摘 CSS）、negative:lua、negative:sql、negative:python 各精确红 1 条；浏览器层 smoke:negative（掐 iframe 回传）红 12、smoke:negative:lua 红 8、smoke:negative:sql 红 7、smoke:negative:sample 红 1、smoke:negative:python 红 9，全部按红 id 集合精确比对、通过数押相对关系 —— 加一门新语言不会让老负例误报。

判据的一条硬规矩：sample/* 七条判据直接跑 SAMPLES 原文，也就是用户打开页面点「运行」看到的第一份代码。v0.3 曾踩过：SQL 默认示例拿 SQLite 保留字 NOTHING 当列别名，自检里 51 条全绿却没一条跑过这份示例，用户一点就 near "nothing": syntax error。现在示例已改成 NULL AS "nothing"，并加了专门负例：把引号去掉必须精确红 sample/sql 一条；v0.4 加的 Python 默认示例同样进这道门。语言判据都用自检自己造的干净输入，天生抓不到「默认示例本身写错了」，这一层只能靠跑原文补上。

体积基线（1024 口径，gzip -9 实测；首屏只算 JS + CSS，不含 HTML 说明文本）：v0.3.1 → v0.4，首屏 JS 11.79 → 13.38 KiB、CSS 1.58 → 1.59 KiB，合计 13.36 → 14.97 KiB（约 +1.6 KiB），全部是契约登记 + 默认示例 + 动态 import 分支，Python 运行时一个字节都没进首屏。切到 Python 编辑器才下载语法高亮 chunk；首次运行再下 python-worker 8.54 KiB + core 四件套 12.89 MiB raw / 6.04 MiB gzip（pyodide.asm.wasm 3.38 MiB、python_stdlib.zip 2.39 MiB、pyodide.asm.mjs 0.25 MiB、lock 0.03 MiB）—— 比 Lua/SQL 高一个数量级，所以引擎必须复用、资产必须同源缓存、绝不预加载。手册第五章 Pyodide 的「约 6.44 MB」是官方 ADR 的 27 请求传输口径，与本轮四件套 gzip -9 的 6.04 MiB 不矛盾，但两个口径不能混算。
