当前范围（v0.6）：JavaScript / TypeScript / HTML / CSS 四门浏览器原生，加上三门 WASM 语言 Lua 5.4、SQLite（SQL）、CPython 3.14（Pyodide），再加两门仅服务端语言 Go 与 PHP，共九门。JS/TS 默认走 Worker（worker.terminate() 能真杀无限循环），HTML/CSS 走 sandbox="allow-scripts" 的 iframe，TypeScript 用官方 transpileModule 动态加载转译。三门 WASM 各自一个 module Worker，全懒加载，不运行就一个字节都不下载。Go / PHP 没有浏览器载体，能力表里只有 server 一个位置，载体下拉会如实显示「仅服务端」。

Go 怎么跑：先 npm run server 启动本机执行节点（servers/local/，Go 单二进制、非 Docker、只绑 127.0.0.1），再选 Go 点运行。节点按 Piston v2 兼容子集提供 /api/v2/runtimes 与 /api/v2/execute：go build + 运行两阶段、仅标准库（GOPROXY=off 零外联）、附加 .go 文件同目录编译、每请求独立临时目录。可用 ?server=<url>&token=<token> 覆盖节点地址。能力表如实登记 isolation=process-only / trust=advisory（结果不可用于判分）、没有 CPU/内存/进程数内核限额、usage.memoryBytes 不填。

PHP 与运行时配置（v0.6）：节点 servers/local/main.go 已抽成内建 builtinSpecs() 规格表，execute() 里不再有任何「语言 if 分支」。Go 是 build+run 两阶段、PHP 是单阶段解释执行（响应不带 compile 字段），正好第一次真机跑通「编译缺省」分支。GET /api/v2/runtimes 每次真探测本机有没有 go / php 能报版本，探测不到就不登记 ⇒ 前端能力表自动置灰并给安装指引，不拿缓存的旧版本骗人。便携式运行时（不在 PATH、没写注册表）在后端配置即可：复制 servers/local/runtimes.json 成 runtimes.local.json（不入库），给对应语言填 path 绝对路径；disabled:true 可显式关掉某门语言（优先于 PATH 探测），path:"" 回退 PATH。网页前台不暴露这个选项，配置是否生效由 npm run check:node 的十四条接口判据证明（source=config / 坏路径自动置灰 / disabled / PATH 回退），probes.runtimePathSource 也会如实回报。PHP 用 -d allow_url_fopen=0 -d allow_url_include=0 关 URL 包装器、php.ini 用宿主机默认；curl / sockets 扩展仍能联网，A′ 没有内核级网络隔离。启动仍是 npm run server。

Lua 实现：wasmoon 1.16.0 跑在独立 module Worker 里，glue.wasm 用 Vite ?url 自托管（默认会去 unpkg，内网/离线不可用，已显式覆盖为同源地址）。Worker 先初始化引擎发 ready，主线程收到后才起墙钟计时 —— wasm 下载与实例化不算进用户代码预算；同步死循环靠 worker.terminate() 真杀。Lua 侧薄壳把 print/io.write 接到输出通道（绕开 Emscripten 行缓冲，无换行也不丢）、io.read 读契约注入的 stdin、os.exit 改成可读错误；第二个 .lua 文件挂到内存 FS，可用 dofile('/helper.lua') 加载。traceAllocations: true 让内存用量与上限都可计数，probes 里能读到 Lua 版本、wasm URL、实际内存用量。

SQL 实现：sql.js 1.16.0 / SQLite 3.54.1 同样跑在独立 module Worker，sql-wasm-browser.wasm 用 ?url 自托管并显式传 locateFile（glue 默认按 scriptDirectory 拼路径，在 module Worker 里不可靠）。不用 db.exec() —— 它会一次性把整个结果集物化进 JS 数组，输出限额根本挡不住内存；改用 iterateStatements + stmt.step() 逐行读，每 64 行批量回传，触到输出字节或行数上限立即停。同一次运行内多语句共享同一个 DB，第二个 .sql 文件作为初始化脚本先执行；NULL/BLOB 显式可读，中文不做全角宽度对齐。能力缺口如实登记：sql.js 没有 wasmoon 那样的 setMemoryMax，所以只有墙钟 + 输出字节 + 行数 + Worker 隔离四道闸，probes.memoryCapability 明写 no-allocator-cap，usage.memoryBytes 一律不填（不拿 0 冒充用量）。无限递归 CTE 靠 terminate() 真杀。

Python 实现：pyodide 314.0.7 / CPython 3.14.2 跑在独立 module Worker。与 Lua/SQL 的单文件 wasm 不同，core 分发是一整套固定文件名的目录（pyodide.asm.mjs / pyodide.asm.wasm / python_stdlib.zip / pyodide-lock.json），glue 按 indexURL 拼路径；Vite 会把 pyodide.mjs 打进带 hash 的 worker chunk，默认前缀必然指错，官方默认更是直接走 CDN。所以由 scripts/sync-pyodide.mjs 在 postinstall / dev / build 三处幂等生成 public/pyodide/（版本精确 pin，运行时产物不入库），Worker 显式传同源 indexURL。首版只跑标准库：core 分发不带 wheel、没有 micropip，禁止自动装包；import numpy 翻译成「第三方包 numpy 不在自托管清单里，不会向 CDN 装包」的可读错误，快速失败且绝不外联。输出用 setStdout/setStderr({batched})、stdin 用 setStdin({read}) 接契约注入的 UTF-8 字节；附加 .py 文件写进内存 FS 的 /pg/ 后可 import helper，路径按净结果判逃逸；顶层表达式返回值回显成 -- 返回值：5，PyProxy 用完 destroy()。引擎复用：正常执行完保留 Worker，靠每次新建的 globals 隔离变量（9.6 MB wasm 只 boot 一次，probes.engineReused 可计数），只有超时 / 取消 / 内部错误才 terminate() 并清空缓存。如实登记的边界：复用期间 sys.modules 共享，不是进程级隔离；没有 allocator 上限，usage.memoryBytes 不填；probes.packageCapability 明写 stdlib-only。

零外联是抓包证据，不是运行时自述：真机冒烟在 CDP 上开 Target.setAutoAttach（flatten），对挂上来的 worker target 逐个再 Network.enable，按已知包仓库域名判红；同时必须抓到 ≥3 条同源 /pyodide/ 资产请求，否则「外部 0 条」只是压根没监听到 Worker 的空证据，直接判失败。dev 与 dist 两层实测都是：同源 /pyodide/ 资产 4 条、外部请求 0 条。v0.6 补一条边界：CDP 只监听浏览器自己的 target，节点进程发出的网络请求它一条也看不到 —— 抓包证明的是前端资产同源自托管，不是节点侧禁网。服务端语言的网络口径只能靠 probes.network 如实登记 + check:node 的行为判据，二者都替代不了内核隔离。

契约先行：RunRequest 已含 target: browser | server、limits（wall/cpu/memory/output）、files[]、stdin；RunResult 已含 exitCode: number | null（浏览器没有退出码，不假装 0）、usage、probes、preview。能力表 Capability 由注册表 active() 推导 —— 没接线就置灰，单测骗不过去。加一门语言只要登记 + 实现 Runner + 注册 + 加示例 + 补端到端判据，UI 一行不改。

★ 服务端路线与官方推荐的分叉（务必别忘）：官方 Piston 推荐 docker run --privileged + 纯 cgroup v2 + Linux（原理是 Isolate inside Docker），官方不支持脱离 Docker，Windows 原生跑不了。本项目刻意选了 A′ 非 Docker 的本机进程节点，依据是威胁模型不同：团队内几个人跑自己的可信片段，不需要内核级隔离。代价是只有进程级限额、结果不可判分、不能对公网开放。一旦要跑不可信代码 / 对外开放 / 判分，必须回切官方 Docker + isolate，不能靠 token 把 A′ 当沙箱。完整决策依据、官方真值、回切清单见分析手册 第十三章 与 servers/local/README.md。

为回切预留的接缝（v0.5 已抽完）：① createRegistry(getMount, serverRunners: Runner[]) 由调用方注入 Runner 实例，不再有绑死 PistonConfig 的 ServerWiring；② trusted 改由 Runner 声明的 isolation / trust 推导（A′ 也是 server，但只有 advisory，不能按位置猜）；③ 服务端语言名从 LANG_DEFS 抽成各后端自有的 languageMap。线协议纯函数统一在 src/runners/server/protocol.ts，A′ 与官方 Piston 共用同一份限额传递与六码状态映射。将来切官方部署只换 main.ts 注入的那一行，契约 / UI / 路由 / 能力表 / 判据零改动。

已知边界：iframe 内同步死循环会冻结标签页（浏览器限制），该模式的超时判据不做自动验证；JS/TS 请用 Worker 载体。首版不支持模块 import/export。预览 iframe 是 opaque origin，event.origin === 'null' 证明不了任何事，代码里靠 event.source + requestId 双重校验。Lua 没有真实网络与文件 IO，每次运行新建引擎（变量不跨运行），没有 REPL session；SQL 是纯内存 DB，每次运行新建，不持久化到 IndexedDB，也没有真实文件/网络。Python 无 socket / threading / 子进程，标准库里凡是依赖这些的模块都不可用；引擎复用不是进程隔离，跨运行可能残留 sys.modules 状态；第三方包要等预置自托管 wasm wheel 才能开。构建时若干 Module "xxx" externalized 警告来自 wasmoon UMD 与 pyodide.mjs 里浏览器下不用的 node 内建模块，dev 与 dist 两层真机都已验证。A′ 节点的边界：无内核隔离（用户代码可读写本机文件、起子进程、联网）、默认 token 只是开发口令、没有 CPU/内存/进程数硬限额、Windows 上 kill 主进程不保证子进程一起退出；每次执行都要 go build（本机约 1.5 秒），且满 CPU 的 for{} 在本机会让编译与终止各慢约 5 秒，所以超时判据只押 status=TO，不押毫秒数。PHP 的边界：本机是 8.0.17（偏旧，片段验证够用，贴近生产建议换 8.3）、php.ini 与扩展随宿主机漂移、语法错误按 Piston 语义只进 stderr + 非零退出码而 run.status 仍为空（判据押 stderr 与 exitCode，不押 status=error）、URL 包装器关了但 curl/sockets 仍可联网。宿主机前置不会消失：每加一门服务端语言都要装工具链（或配 runtimes.local.json 的 path）+ 在节点 spec 表登记，跨机器版本不一致就没有可复现性。

验收（v0.6）：npm run verify（类型检查 + 77 条单测 + 构建）；npm run smoke 用本机 Chromium + CDP 打开 ?selftest=1 跑真浏览器端到端判据（100 条：98 绿 / 2 条按白名单记账跳过，跳过的正是 iframe 同步死循环两条），npm run smoke:preview 在 dist 产物里跑同一套判据；npm run check:node 在独立端口重启节点四次，用 14 条接口判据证明配置路径 / 动态探测 / disabled / PATH 回退都真生效。十三组拆线负例：单测层 negative（摘 CSS）、negative:lua、negative:sql、negative:python 各精确红 1，negative:go（摘空两门）红 3、negative:php（只摘 PHP）红 3；真机层 smoke:negative 红 12、smoke:negative:lua 红 8、smoke:negative:sql 红 7、smoke:negative:sample 红 1、smoke:negative:python 红 9、smoke:negative:go（摘整个服务端 Runner）红 27、smoke:negative:php 红 15，全部按红 id 集合精确比对、通过数押相对关系 —— 加一门新语言不会让老负例误报。排障纪律：真机自检期间不要改 index.html / 静态 HTML，Vite HMR 会 full-reload 页面把自检反复打断（表现为「150 秒没产出自检报告」但代码本身没问题）；PLAYGROUND_SELFTEST_TIMEOUT_MS 可缩短等待窗口定位。

判据的一条硬规矩：sample/* 九条判据直接跑 SAMPLES 原文，也就是用户打开页面点「运行」看到的第一份代码。v0.3 曾踩过：SQL 默认示例拿 SQLite 保留字 NOTHING 当列别名，自检里 51 条全绿却没一条跑过这份示例，用户一点就 near "nothing": syntax error。现在示例已改成 NULL AS "nothing"，并加了专门负例：把引号去掉必须精确红 sample/sql 一条；v0.4 加的 Python、v0.5 加的 Go、v0.6 加的 PHP 默认示例同样进这道门（Go / PHP 那份还得先有本地执行节点在线且 PHP 已就绪）。语言判据都用自检自己造的干净输入，天生抓不到「默认示例本身写错了」，这一层只能靠跑原文补上。

体积基线（1024 口径，命令行 gzip -9 实测；首屏只算入口 JS + CSS，不含 HTML 说明文本）：v0.6 首屏 JS 16.16 KiB + CSS 1.59 KiB = 17.76 KiB（比 v0.5 的 17.08 KiB 约 +0.68 KiB，是 PHP 登记、默认示例、动态 import 分支与服务端 Runner 多语言声明；本机 PHP / Go 运行时与执行节点一字节都没进前端产物）。切到 Go 编辑器才下 go-CTD25R5P.js 1.28 KiB 语法包；切到 PHP 编辑器才下含 phpLanguage 的 dist-1ZStK4Cv.js 27.17 KiB（@lezer/php 连同 HTML/CSS/JS 混合解析依赖，是九门里最贵的语法包，仍不进首屏）；执行走本机约 10.6 MB 单二进制（不入库、不下载）。注意 Vite 自己打印的是 1000 口径，与这里差 2.4%，别混算。历史账：v0.3.1 → v0.4，首屏 JS 11.79 → 13.38 KiB、CSS 1.58 → 1.59 KiB，合计 13.36 → 14.97 KiB（约 +1.6 KiB），全部是契约登记 + 默认示例 + 动态 import 分支，Python 运行时一个字节都没进首屏。切到 Python 编辑器才下载语法高亮 chunk；首次运行再下 python-worker 8.54 KiB + core 四件套 12.89 MiB raw / 6.04 MiB gzip（pyodide.asm.wasm 3.38 MiB、python_stdlib.zip 2.39 MiB、pyodide.asm.mjs 0.25 MiB、lock 0.03 MiB）—— 比 Lua/SQL 高一个数量级，所以引擎必须复用、资产必须同源缓存、绝不预加载。手册第五章 Pyodide 的「约 6.44 MB」是官方 ADR 的 27 请求传输口径，与本轮四件套 gzip -9 的 6.04 MiB 不矛盾，但两个口径不能混算。
